## Goal

Record exactly what the openkan base application already ships today.

## What's already built

**Server**
- `kanban/server.ts` — Node `http` server on `http://127.0.0.1:7777`, SSE endpoint at `/api/events`, REST API at `/api/tasks`

**Board**
- `kanban/board.ts` — five-column kanban state (Backlog, To Do, In Progress, Review, Done), JSON state stored in `.ok/state.json`
- `kanban/mdx.ts` — task-to-MDX artifact conversion, writes `.ok/tasks/tsk-<id>.mdx` and later `tasks/<id>/task.mdx`

**Initial agent operations**
- `kanban/server.ts` — four agent operations implemented by the local API: `kanban_add`, `kanban_move`, `kanban_start`, `kanban_view`
- `kanban/server.ts` — local HTTP operations backed by `kanban/board.ts`

**Web UI**
- `web/index.html` + `web/app.js` — localhost board UI with column rendering and SSE live updates

**Artifact storage**
- `.ok/tasks/tsk-<id>.mdx` (flat) / `tasks/<id>/task.mdx` (M7+ per-task directory) — MDX artifact per task
- `.ok/sessions/` — session artifacts

## Acceptance criteria

All of the following are green today:

- [ ] `kanban/server.ts` serves the board on `127.0.0.1:7777` using Node's built-in `http` server
- [ ] Board has five columns: Backlog, To Do, In Progress, Review, Done
- [ ] `kanban_add` tool creates a task and writes its MDX artifact
- [ ] `kanban_move` and `kanban_start` update task column in state
- [ ] `kanban_view` returns the board snapshot
- [ ] SSE endpoint pushes board updates to the web UI
- [ ] Task MDX artifacts live under `.ok/tasks/`
