A kanban board that both you and Claude Code read and write.

Tasks, goals, agent activity, and decision history — stored as plain files inside your repository. A local dashboard on 127.0.0.1:7777. A control plane your coding agent already understands. No account, no hosted service, no telemetry.

Install OpenKan

$ npm install -g @polderlabs/openkan
$ cd /path/to/your/project
$ ok init
$ ok start
# dashboard opens at http://127.0.0.1:7777/

What you get

Five-column board

Backlog, To Do, In Progress, Review, Done. Drag-and-drop, keyboard shortcuts, right-click menus. Subtasks are nested; archived items are out of the way.

Tasks are plain files

Each task lives at .ok/tasks/<id>/task.mdx. Frontmatter drives the dashboard. Read, edit, and diff them in any tool — your editor, git, or your editor's quick-open.

Claude Code native

Installs a Claude Code agent and skill so the assistant can list, claim, comment, and move tasks without bespoke wiring. Ask Claude to "pick up the next review item" — it just works.

Chat sidebar with tabs

An embedded chat panel beside the board. Discuss a task, attach a screenshot, link a session. Multiple conversations stay open in tabs while you work.

Local-only, no telemetry

Binds to 127.0.0.1. Nothing leaves your machine. Audit-friendly by construction: every change is a file write you can git diff.

Live preview, source links

Task MDX renders inline TSX previews. Source drift is detected automatically: the dashboard flags tasks whose origin file has changed and offers re-derive.

Built for the actual workflow

OpenKan is shaped by three different kinds of users hitting the same repo at the same time. The control plane makes every action legible without giving anyone a special seat.

👤 The maintainer

Owns the project, reviews pull requests, decides priorities. Reads the board on Monday, skims the changelog, and asks Claude Code to "triage the review column".

  • Sees source drift on stale tasks
  • Right-clicks a card to reopen, archive, or change owner
  • Drags a card to done; the agent's note auto-attaches

🤖 The coding agent

Claude Code has a single, durable source of what is in flight. It claims work with ok task claim, emits heartbeats, and writes the changelog entries you'd write by hand.

  • Pulls context from the task MDX (acceptance, source link, owner)
  • Writes a session artifact under .ok/tasks/<id>/session/
  • Marks the task done only after make check passes

📝 The reviewer

Joins the project to give feedback. Opens the dashboard, leaves an inline comment on the rendered MDX, tags the task, and moves on. No account needed.

  • Inline comments attach to a task and survive restarts
  • Tagged threads resolve back to "open" or "done"
  • No login: the git user name is the identity

How it fits together

  1. 1

    Install once

    npm install -g @polderlabs/openkan ships the CLI, the local server, the Claude Code agent, and the dashboard's static assets.

  2. 2

    Initialize the project

    ok init creates .ok/ in your repo with a config file, an index, and an empty tasks directory. Safe to run twice; idempotent.

  3. 3

    Start the dashboard

    ok start binds the server on 127.0.0.1:7777 and broadcasts board changes over Server-Sent Events. Closing the terminal stops it; ok stop does the same from another shell.

  4. 4

    Use the dashboard and the agent

    Drag a card in the UI, or have Claude Code pick it up. Both paths write the same MDX. git log shows your history and the agent's history, side by side.

"The .ok/ folder is the source of truth. The dashboard, the CLI, and Claude Code are three views over the same plain files."
