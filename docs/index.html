Kanban for you
and your agents.

OpenKan is a local-first kanban board with a Claude Code control plane. Your .ok/ directory holds plain MDX; the dashboard, the CLI, and the coding agent all read and write the same files. No hosted service, no account, no telemetry. 

$ npm install -g @polderlabs/openkan
$ ok init           # create .ok/ in your repo
$ ok start          # dashboard at 127.0.0.1:7777

What you get

A complete control plane, in plain files.

Six primitives that compose. Each one is just files on disk and a command in the CLI. Nothing is locked in.

01

Five-column board

Drag cards across Backlog → To Do → In Progress → Review → Done. Subtasks nest inside their parent; archived items leave the board but stay on disk.

BacklogTodoDoingReviewDone
tsk-9k  Add session telemetry  
tsk-2x  Migrate storage       
tsk-7y  Fix watcher debounce
02

Tasks are plain files

Each task lives at .ok/tasks/<id>/task.mdx with a frontmatter block. Diff them in git, edit in your editor, search with grep, fork the repo and take them with you.

---
id:      tsk-7pQ3nXk9
title:   Rebase feature/auth
status:  in_progress
priority: high
---

# Rebase feature/auth onto main

Re-apply commits, re-run CI.
03

Claude Code native

The package installs a Claude Code agent and a skill. The assistant can list, claim, comment, and ship tasks without bespoke wiring. Just ask: "pick up the next review item."

Why local

Different by design.

Hosted kanbans are great — until you need an agent to read your board, or your security team asks where the data lives, or you want to fork a project and take its history with you. OpenKan is built for those moments.

OpenKan

  • ✓ Storage is your repo, in .ok/
  • ✓ Coding agent reads & writes the board
  • ✓ Works offline; no account needed
  • ✓ One port: 127.0.0.1:7777
  • ✓ Fork a project, take its tasks with you
  • ✓ Audit trail is git log

Hosted kanbans

  • × Storage lives on someone else's server
  • × Custom API integrations to wire an agent in
  • × Requires login; degrades offline
  • × Webhooks, secrets, OAuth dance
  • × Migration out is a project
  • × Audit log is a paid plan

Workflow

Three users, one source of truth.

OpenKan is shaped by three different kinds of users hitting the same repo at the same time. The control plane makes every action legible without giving anyone a special seat.

👤

The maintainer

You · the human in the loop

  • Reads the board on Monday, skims the changelog
  • Asks Claude to "triage the review column"
  • Drags a card to done; the agent's note auto-attaches
🤖

The coding agent

Claude Code · your pair-programmer

  • Pulls context from the task MDX (acceptance, source link, owner)
  • Claims with ok task claim, emits heartbeats
  • Marks done only after make check passes
📝

The reviewer

Anyone with read access to the repo

  • Inline comments attach to a task and survive restarts
  • Tagged threads resolve back to "open" or "done"
  • No login: the git user name is the identity

From zero to board

Four steps. Two minutes.

  1. 1

    Install once

    npm install -g @polderlabs/openkan ships the CLI, the local server, the Claude Code agent, and the dashboard's static assets.

  2. 2

    Initialize the project

    ok init creates .ok/ in your repo with a config file, an index, and an empty tasks directory. Safe to run twice; idempotent.

  3. 3

    Start the dashboard

    ok start binds the server on 127.0.0.1:7777 and broadcasts board changes over Server-Sent Events.

  4. 4

    Use the dashboard and the agent

    Drag a card in the UI, or have Claude Code pick it up. Both paths write the same MDX. git log shows your history and the agent's history, side by side.

"The .ok/ folder is the source of truth. The dashboard, the CLI, and Claude Code are three views over the same plain files."
