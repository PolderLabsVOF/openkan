## What this is

openkan is a local-only OpenCode plugin that runs a localhost kanban at `http://127.0.0.1:7777`. It already ships with a five-column board, custom OpenCode tools, MDX artifacts, and SSE updates.

This directory contains the milestone plan. The earlier milestones (M0–M6) are about the **kanban as a control surface** — pull tasks from project docs, link back to the source, detect drift, structure handoffs. The newer milestones (M7–M9) pivot to the **MDX as the workspace** — a tasks index pointing to rich MDX artifacts, an interactive review surface with inline comments, and live TSX previews embedded in the MDX so the agent can ask the user a structured question and the user can answer in-place.

## What's shipped

- **M0** — base plugin: five-column board, four custom tools, MDX artifacts, SSE updates.
- **M1** — `kanban_import`: scan `.md` / `.mdx` files for `- [ ]` and create one Backlog task per hit. Idempotent on unchanged content.

The M7–M9 arc made the task MDX the primary artifact and the board a thin pointer. The M10–M11 arc turns the localhost page into a small dashboard: tabs for Tasks / Changelog / Contributors, a settings page, archive out-of-board tasks, attribute work to people via `git log`, and give the agent a `/organize` command plus auto-progress notes. The M12 arc adds full-text search, atomic bulk operations, a canonical MDX template, real-time agent progress tracking, and an artifact viewer in a new tab. The M13–M14 arc adds keyboard control, a command palette, live file-watch, and cross-tab sync. M15 adds edit/subtasks, artifact viewer polish, changelog filter, and a right-click menu refactor. M16 layers the Docs tab (project `docs/` file browser + sanitized MDX viewer), multi-project support (`~/.config/openkan/projects.json` registry), and comment authorship (git user / `agent:<name>` with avatar + timestamp in the UI). M17 is the UX consistency pass — click-to-edit inline on titles and descriptions (no more modal round-trip), the settings dialog reorganized into a left-rail of sections (Project / Server / UI / Sandbox / Import / Contributors / Advanced) backed by `GET /api/config-sections` and `PATCH /api/config-sections/:sectionId`, a unified design-token layer across buttons / chips / fields / transitions, right-click context menus everywhere, and archived items hidden by default.

## Cut list

The following were in the original technical plan and are deliberately excluded:

- **MCP server** — local-only tool; agents can read task MDX files directly.
- **Multi-agent adapters** (Claude/Codex/custom) — file-based handoff is agent-agnostic.
- **SQLite** — JSON state files are sufficient for single-user local operation.
- **LAN mode** — localhost-only by design.
- **Auth tokens** — single-user, no remote access.
- **Cloud sync / GitHub/Linear/Jira sync** — out of scope for local-first MVP.
- **LLM enrichment** — deterministic parsing only; no API key required.
- **Semantic duplicate detection** — stable ID scheme handles exact duplicates.
- **Telemetry** — no external calls, no tracking.
- **.kanbanignore machinery** — future option; not needed yet.
- **Patch generators / drift reports** — planned in M3 as a banner, not a full report engine.
- **Event log JSONL** — state transitions stay in the JSON state file for MVP.
- **Package monorepo split** — single package; no apps/packages split.
- **Reactive / real-time push for the iframe sandbox** — the sandbox does not stream; the user re-renders on submit.
